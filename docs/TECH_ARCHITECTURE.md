# 技术架构

## 阶段一选型

**原生 HTML + CSS + JavaScript ES Modules，WebGL 动态立绘与 CSS 场景视觉。**

目前产品风险在于陪伴体验、关系状态和碎片化对话是否成立，而非大规模实时渲染。因此先用浏览器技术降低 Windows 开发门槛、支持窄屏和 AI 协作。运行不依赖包管理器或外部库，代码可由静态服务器直接提供。

Godot 4 适合后来需要场景编辑器、骨骼动作、引擎工具链和原生包体时重新评估。Three.js 适合在既有 Web UI 中逐步替换角色舞台，并沿用浏览器渠道。是否迁移由性能、角色表达和打包需求共同决定；现在不强行预判最终引擎。

## 模块边界

- data/：角色定义、对话、短信和剧情场景数据。用稳定 ID 关联存档，不以角色数量分支硬编码。
- src/core/affection.js：好感增减与等级判断。
- src/core/game-state.js：按角色保存关系、消息、选择和剧情旗标；提供事件方法。
- src/core/save.js：浏览器本地存档读写与异常回退。
- data/companionship.js：短相处的节点图、选择、心情记忆和问候条件。
- src/core/conversation.js：独立对话状态机，记录本次节点和玩家选择。
- src/core/ambient-audio.js：用户手动开启的 Web Audio 合成雨声，隐藏页面暂停。
- src/ui/character-stage.js：角色展示适配器。当前加载角色立绘并呈现表情反馈、待机动画和交互热点；未来可以替换 Three.js 实现。
- src/ui/portrait-renderer.js：WebGL 局部 UV 形变与表情纹理混合，约 30 帧/秒；眨眼、微笑、头部/胸口/手部细微运动。没有骨骼或真正三维深度。
- src/ui/encounter-panel.js：逐字对白和选项呈现，可跳过打字与回看；不重建角色舞台。
- src/ui/*-view.js：独立页面视图，接收角色和状态数据。
- src/app/main.js：导航和用户事件编排，不承载角色文本与故事内容。

## 状态流向

UI 用户操作 → 对话节点/核心状态动作 → 按角色 ID 更新本机存档 → 订阅更新。主页只更新关系、手记和导航；角色实例持续存在，避免计分或消息通知打断表情。离开主页时释放事件监听、动画帧、纹理和缓冲区。其他页面按状态重新绘制。

`presentation` 将原画、闭眼/微笑表情路径和椭圆热区存入角色配置。命中测试使用实际图像平面的 `getBoundingClientRect()` 反算归一化坐标，因此适用于宽窄屏、裁切和近景变换。场景背景不参与身体呼吸形变。GPU 不可用或上下文丢失时保留原图；图片下方始终有后备图层。

存档继续使用 `fog-harbor-save-v1`；读取旧角色状态时填充 `memories`、`journal`、`awards`、`pendingMessages`、`sceneSelections` 等缺失字段。写入失败会通知界面，但本次会话继续工作。奖励按本机日历日期和相处 ID 去重；这只是本机单人原型规则，不提供防篡改保证。

相处完成后将延迟来信写入持久队列，打开网页和运行期间定时投递；页面关闭时没有系统推送。短信回复按消息 ID 去重。剧情选择先展示 `sceneResponse`，再前进；重玩逐句进行，结算不重复奖励。未来增加角色可复用同一状态和舞台接口，并为该角色配置专属相处、短信及剧情数据；当前入口仍只呈现一名男主。

## 后续能力边界

当前用 CharacterStage 作为 2D/3D 交界。消息服务、云端账号、AI 动态对话、电话、语音、换装、卡牌、抽卡与战斗均未实现，不伪装成已连接能力。建议按以下触发条件再引入：

- Three.js/Unity/Godot 实时角色：已有明确表情、动作、光照和性能需求。
- PWA/移动端壳：已有持续使用需求与离线资源清单。
- 云端服务：跨设备同步或主动推送成为核心价值，并明确隐私与成本模型。

## 运行与调试

在 Windows PowerShell 中运行根目录的 run-local.ps1，再用浏览器打开脚本显示的本机地址。数据与文案使用原生模块，避免 file:// 的 ES Module 跨域限制。该服务器只绑定 127.0.0.1。

开发检查：`node scripts/check-interactions.mjs` 使用独立内存存档覆盖迁移、所有对话分支、每日去重、持久短信、单次回复、剧情选择/重玩、缩放坐标、存储异常和版本元数据，不修改玩家浏览器进度。发布前还需以真实浏览器检查窄屏按钮可点、表情加载、手机底栏避让和完整链路。

## GitHub Pages 缓存更新

项目没有注册 Service Worker，因此不会被旧的离线缓存长期拦住。入口 HTML 使用重新验证提示；HTML、CSS、每个 ES Module 导入和角色立绘 URL 都带同一发布版本查询参数。发布新版本时，先更新 changelog，再运行 `./scripts/update-cache-version.ps1 -Version x.y.z`，检查 `index.html` 和 JS 导入的版本一致后提交。侧栏底部会显示当前版本，方便确认网页加载的是哪次发布。浏览器/CDN 对 HTML 元数据的处理仍受托管服务影响；若 Pages 尚未发布，版本号和缓存参数都不会生效。
